# FAILURES · 踩坑记录

> 只记**这次做的时候真踩到的**坑，不写「据说可能」的风险。
> 每条四段：现象 / 根因 / 修法 / 以后怎么防。没有修法的条目不许进来。

## F1. 示例语料全被判「悬空」，但文件明明在

**现象**：demo 里 8 条单元全部报 `文件不存在：...\corpus\identity.md`，而文件就在旁边。
**根因**：`resolveUnitPath` 只认 `baseDir` 这一个参数名；而 `checkup` 一路传的是 `dshHome`。
两个名字指的是同一件事，实现却只读其中一个，缺省值就落回了全局默认目录。
**修法**：改成 `baseDir ‖ dshHome ‖ DSH_HOME` 三选一（取第一个非空）。两个旧调用点都不用改。
**防**：**同一个概念只允许一个参数名**。已经有第二种叫法时，在实现层兼容，不在调用层统一 ——
后者要改十几个地方，等于制造新的漂移。

## F2. 路由层把 `baseDir` 吃掉了

**现象**：给 `route()` 传了 `baseDir`，注入仍然按默认目录解析路径。
**根因**：`router` 调 `buildText()` 时只挑了两个字段（`budgets` / `dshHome`）往下传，
新增的字段被静默丢弃。
**修法**：显式透传。
**防**：**中间层要么转发整个 opts，要么在签名里写清「只接受这几个字段」**。
悄悄白名单转发是最坏的一种 —— 调用方以为传到了，实际被吃掉，而且没有任何报错。

## F3. demo 的输出打印了两遍

**现象**：一次 demo 把注入文本打了两次，一次被解构参数吃掉一大半。
**根因**：adapter 的 `applyContext()` 直接往 stdout 写，而 demo 自己又打印了一遍
`lastRendered()`。
**修法**：adapter 加 `quiet` 开关，demo 用它自己排版。
**防**：**库负责数据，脚本负责排版**。一个函数不要既返回结果又当副作用输出。

## F4. 私人名字跟着源码进了发布目录

**现象**：`gate` 报 3 个 `src/*.js` 与 `docs/BOUNDARY.md` 命中私人词。
**根因**：这些文件是从运行线**原样复制**的，注释里写着作者名与用户名。
**修法**：批量把注释里的名字改成中性词（「本工具 / 用户」），判据行的表述改成「查外部名单」。
**防**：**复制之后的第一件事就是跑 gate**，而不是等文档写完再跑 —— 越晚成本越高。

## F5. gate 自己的注释触发了 gate

**现象**：`gate` 命中 `scripts/gate.mjs` 本身。
**根因**：注释里写了「绝对路径的字面形状示例」（真的写了用户目录路径），而规则就是匹配这个形状。
**修法**：注释改成描述「Windows 用户目录 / macOS 用户目录」，不写具体字面量。
**防**：**检查器与被检查内容用同一套模式时必须自扫**；更彻底的做法是把具体词表放仓库外。

## F6. 示例清单的 keys 太窄，红线 3/4

**现象**：`route-probe` 报 redline 3/4、改写召回 7/10 —— 「帮我排个错」命不中「排错」。
**根因**：keys 是按「标准说法」写的，而真实说法是「排个错」「取一下那个页面」。
**修法**：按失败句补了 8 个真实说法键，再跑 → 4/4 + 10/10。
**防**：**先有回归集，再有词表**。顺序反过来就会写出一堆「按理说应该能命中」的键。

## F7. 写入的注释里出现乱码字符

**现象**：`trace-stats.mjs` 的一行注释里出现了替换字符（`���`）。
**根因**：一次大段中文内容写入时被截断/损坏，且当场没有校验。
**修法**：按行定位修掉，并 `node --check` 确认语法。
**防**：**写入后立刻做一次机器校验**（语法检查 / 匹配关键字符串），别等人眼发现。
中文文档与脚本尤其容易在编码边界上出问题。

## F8. 「六类体检全绿」其实因为扫的是空目录

**现象**：`manifest-checkup` 一开始就绿，但那时示例语料还没写。
**根因**：检查项在拿不到文件时按「跳过」处理，跳过不计失败。
**修法**：让 `manifest-checkup` 在清单加载失败时直接 `level=error`；
`bom` 这类「扫 0 个文件」的情况应显式打印数量，让人能看出异常。
**防**：**每个检查都必须报告扫描数量**。数量为 0 的「通过」是最危险的绿灯。
