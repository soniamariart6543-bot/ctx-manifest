# WHY · 为什么这么设计

> 这份文档只回答「为什么」，不讲解用法。用法看 README。
> 目标读者：准备改这套东西的人 —— 你得先知道哪些决定是**故意的**，再去动它们。

## 1. 为什么不直接写一个大 prompt

因为大 prompt 的失败是**静默**的。

一个 5000 字的 prompt 里，某段话从「有用」变成「过期」时没有报错：模型照样回答，
只是答得不如以前。你唯一能察觉的方式是「感觉最近有点笨」——而那不可复现。

拆成清单之后，每段话有了三个可检验的属性：

- **在不在**（文件是否存在 → 悬空检查）
- **该不该进**（这轮命中了吗 → trace 里的 reasons）
- **占多少**（预算与裁剪 → chars / clipped）

设计里所有「麻烦」都是为这三件事服务的：宁可多写一个 JSON 字段，也不要一个说不清的行为。

## 2. 为什么分四层，而不是平铺

不是因为分层好看，是因为**四种东西的检索粒度本来就不一样**：

| 层 | 什么时候需要 | 为什么不能混 |
|---|---|---|
| `L1` 恒注 | 每一轮 | 身份与输出契约是「无条件成立」的，混进条件层就会「有时有、有时没有」 |
| `L2` 条件 | 命中关键词时给一行 | 这类是**纪律**（改文件先备份），需要时提一句就够，不需要时不占预算 |
| `L3` 长尾 | 命中时给「标题 + 路径 + 摘要」 | 冷门知识（某个软件的坑）十天用一次，全文常驻是浪费 |
| `anchor` | 固定指针 | 交接文件这类「永远指向最新状态」的东西，只需要一句「去读末节」 |

混在一起的后果是可预测的：条件内容会污染恒注区，预算被冷门知识吃掉，最后谁都不满意。

## 3. 为什么用关键词 + 同义表，而不是向量检索

**取舍很清楚，不是不知道有更好的方案：**

| 维度 | 关键词 | 向量 |
|---|---|---|
| 可解释 | 命中理由能逐字打印（`keys: 改文件`） | top-k 说不清为什么是这几条 |
| 可 diff | 改一个词，diff 一行 | 改一个词，整个向量空间都变了 |
| 依赖 | 零（无模型、无服务、无网络） | 需要嵌入模型 + 向量库 |
| 召回上限 | 有（换个说法就命不中） | 高 |

选关键词的理由是：**这套东西的价值在「可审计」，不在「最强召回」**。
天天要回答「为什么这轮注入了这段」，向量给不了这个答案。
代价也写在明处：召回有天花板，到顶就把数字记下来（见 FALSE-GREEN.md 的「触顶判定」），
而不是无限加同义词把词表变成不可维护的一坨。

## 4. 为什么给「指针」而不是全文

上下文是有限资源：token 越多，模型对其中任意一段的注意力越薄（业界称之为 context rot）。

所以「即时检索」优于「全量预加载」：清单里放**轻量标识符**（文件路径 + 一句摘要 +
一句「什么时候该读」），需要细节时再读文件。

这也是为什么 L3 的摘要要写「何时读」——不给时机，模型判断不出该不该去读，指针就白给了。

## 5. 为什么要每轮写 trace

因为**没有 trace 的注入系统等于黑盒**，而黑盒只能靠感觉调参。

trace 一行 JSON，记下：这轮命中哪些单元、每个单元的命中理由、分层字符数、预算余量、
被裁剪的、悬空的、进冲突缓冲的。它回答三个问题：

1. 这一轮注入了什么、为什么（可解释）
2. 字符都花在哪了（性能 / 预算）
3. 这周比上周好了还是差了（趋势）

代价是每轮多写一个文件。收益是：任何「最近变笨了」的怀疑都能在十秒内变成数字。

## 6. 为什么清单改动要人审，不做全自动

自动抽取（从对话里抽「值得记的事实」再写进清单）看起来很美，但它有一个致命缺陷：
**抽错的事实会被固化，而且事后很难审。**

真实的失败长这样：抽取器把「用户说要 A」抽成「用户偏好 A」，之后每一轮都按 A 处理，
而用户其实早就改主意了。这类错误不会报错，只会让系统越来越偏。

所以这里的边界是：**机器可以提候选，人负责签字。** 签字记录本身也是资产 ——
下次抽到同一个词，不用重新想一遍「为什么当初没要它」。

## 7. 为什么边界要冻结（BOUNDARY）

开源一套「体系」，不是开源一整套「系统」。

体系 = 装配逻辑（换个人、换台机器都成立）
系统 = 这个人是谁、这台机器怎么维护（只对作者成立）

边界一旦模糊，两种坏结果都会出现：私人内容泄漏，或者通用部分被私人假设污染
（比如把某个人的路径写进默认值）。

所以 BOUNDARY.md 逐文件打标，只问三个问题：换人成立吗、换机器成立吗、
它讲的是「怎么装配」还是「装配什么」。**没有「待定」这一项。**
