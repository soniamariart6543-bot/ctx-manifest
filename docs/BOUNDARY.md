# BOUNDARY · 边界冻结（E0）

> 本文回答一个问题：**这个仓库里该有什么，不该有什么。**
> 判定只问三句（与计划书 §2.2 一致）：换一个人用还成立吗 / 换一台机器还成立吗 / 它讲的是「怎么装配」还是「装配什么」。
> 状态：E0 完成（100% 文件有处置，无「待定」）。行数为 2026-10-26 副本实测值。

## 1. 一句话定位

开源的是**体系**（装配逻辑 + 可迁移的方法），不是**系统**（某个人的档案、某台机器的运维）。

## 3. 三条灰色地带的裁定

| # | 疑点 | 裁定 | 理由 |
|---|---|---|---|
| 1 | `indexer.js` 是不是该私留？（它读知识库目录） | **进包** | 它读的是「清单里声明的路径」，不预设目录名；示例语料照样能生成索引 |
| 2 | `store.js` 的打戳里有时间戳与路径 | **进包** | 打戳本身是通用机制（记录「这个单元上次被命中的时刻」）；路径来自调用方传入的 `dshHome`，改为必填参数即可 |
| 3 | `checkup.js` 的检查项里有「私人」味道（覆盖缺口） | **进包** | 它检查的是「登记 vs 实存」的一致性，是契约问题不是隐私问题；示例语料自带一份覆盖清单 |

## 4. 与计划书附录 A 的行数差异（如实记录）

计划书附录 A 记的是 1824 行可开源主体；本次实测副本合计 **1790 行**（9 个主体文件）。差异来自统计口径（`Measure-Object -Line` 不计无换行的末行 / 计划书引用的是改造前快照）。**判据以实测为准**，附录 A 的 1800 行量级结论不变。

## 5. 边界冻结后的护栏

| 护栏 | 做法 |
|---|---|
| 私人字符串 | 提交前跑 `node scripts/gate.mjs`（敏感词表放仓库外的私有文件，不落进仓库），结果必须为 0 |
| 复制来源 | 只从 `_raw/` 出发；`_raw/` 只白名单复制，禁止整目录拷贝 |
| 仓库历史 | `git init` 全新历史，不从运行线继承任何提交 |
| 双线方向 | 单向（运行线 → 发布线），手动挑，不自动同步 |
