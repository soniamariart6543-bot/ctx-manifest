# 工作流（示例）

> 条件层素材：平时不注入，命中关键词时才给一行指针，需要细节再读进来。
> 这就是「即时检索」—— 用路径 + 一句话摘要替代全量预加载。

## 改文件前先备份

顺序固定，不许颠倒：

1. **备份**：`copy file file.bak-<时间戳>`（或 `git stash`）
2. **改**：只改该改的地方，不顺手动别的
3. **语法检查**：脚本类必须过 `node --check` / `Parser::ParseFile`
4. **比对**：改完算哈希，和备份比 —— 一致说明「没改成」，不一致才是「改成了」

为什么这么较真：一次「以为改了其实没改」能浪费半小时，而且会得出错误的结论。

回滚永远从备份目录开始，不靠记忆重写。

## 会话交接

跨会话的上下文不靠记忆，靠一份**只追加**的文件：

- 每轮结束时追加一节：改了什么（文件 + 哈希）/ 怎么回滚 / 当前真实状态 / 下一步
- 下一轮开场**只读最后一节**，别从头翻
- 节点数会一直涨，别把数字写死在别处

判据：一个新会话读完最后一节，能在不问你任何问题的前提下接着干。

## 单一入口

状态、检查、回滚 —— 各自只需一条命令。命令多到记不住，等于没有。

## 提交纪律

- 每次改动一次提交，信息写清「改了什么 + 为什么」
- 收尾时工作区必须是干净的；脏改动堆着不回滚，等于没有版本控制
