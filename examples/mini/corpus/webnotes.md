# 网页抓取（示例）

> 这一篇演示「条件层 anchors」：清单里 `path` 带 `#锚点`，注入时只给一行指针，
> 真正需要细节时模型才读这一段。

## 抓取规矩

**三级降级，按顺序试，不要一上来就上浏览器：**

| 级 | 手段 | 什么时候用 | 代价 |
|---|---|---|---|
| 1 | 直连 HTTP | 静态页、API、Markdown 源 | 毫秒级 |
| 2 | 真实浏览器 | 需要 JS 渲染、直连被拦 | 秒级，吃内存 |
| 3 | 手工确认 | 登录墙 / 验证码 | 得问人 |

**落盘优先**：抓到的东西先原样存一份（`grab/<日期>-<标题>.md`），再清洗。
理由：清洗规则会改，原文不会 —— 规则改错了还能重跑，原文丢了就没了。

## 常见拦截与识别

| 现象 | 多半是 | 处理 |
|---|---|---|
| 返回 200 但正文为空 | JS 渲染 | 上浏览器 |
| 403 / 429 | 反爬或限流 | 降速、换 UA，仍不行就停 |
| 302 跳登录 | 登录墙 | 停，问人 |
| 卡住不返回 | 超时 | 设超时（≤45s），到期放弃并记录 |

**不要做的事**：不为了绕过验证码做自动化；不伪造 Cookie 冒充已登录；不把整站镜像下来。

## 清洗

1. 去掉导航 / 页脚 / 广告块
2. 统一空白与换行（正文里不要留连续空行）
3. 保留原文标题层级
4. 记下来源 URL 与抓取时间 —— 没有来源的正文等于没有证据

## 判据

- 一次抓取必须能回答：**这条信息从哪个 URL、什么时候取的**
- 抓取脚本对同一输入两次运行，输出字节一致（除了时间戳）
